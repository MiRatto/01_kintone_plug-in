# ミラっとExcel_更新編

Excelのキーに一致するkintoneの既存レコードを、最大100件ずつ更新するプラグインです。

作者：ミラ／公開対象：version 8

## ダウンロードと導入

このリポジトリのReleasesから、添付された `miratto-excel-update-v8.zip` をダウンロードし、解凍せずkintoneへ読み込みます。
自動生成の「Source code (zip)」「Source code (tar.gz)」はkintone用のプラグインZIPではありません。
利用前に[利用条件・免責事項](TERMS.md)をご確認ください。

対応ファイル：`.xlsx`、`.xls`、`.xlsm`、`.xlsb`。パソコン版kintone用です。モバイル版は対象外です。マクロを実行せず、数式は保存済み計算結果を使います。

## 操作

1. 設定画面で「開始セル」「読込終了列」「終了判定列」を指定します。範囲・終了条件・raw値は新規登録v16を引き継いでいます。
2. 必須・重複禁止の両方が設定された通常フィールドを、更新キーとして1〜3項目指定します。フィールドコード（フィールド名）から選び、各キーに対応するExcel列も選びます。
3. 設定を保存し、アプリを更新します。
4. 一覧の薄い水色・濃い青枠の「Excel一括更新」から、Excelとシートを選びます。更新キーの列はプレビューで濃い水色になります。
5. OKで照合・更新を開始します。一致しない行は新規登録せず、最後に「△エラー」とExcel行番号・キー・理由を表示します。
6. 更新があった場合だけ、結果画面のOK後に一覧を1回再読み込みします。処理エラー・キャンセル・0件では自動更新しません。

## 数式の取り込み

数式はExcelに保存された計算結果を読み込みます。更新対象の有効行に計算結果のない数式があれば、セル位置を示し、更新APIを送る前に全体を停止します。Excelで再計算して保存すれば通常どおり取り込めます。通常の空欄セルとは区別し、空欄・重複キーでスキップする行の更新セルは評価しません。

## 更新するフィールド

更新キー以外は、新規版と同じ絶対列番号です。A列＝E_001、B列＝E_002。B列開始でもB列はE_002です。設定範囲のフィールドは存在する必要があります。範囲外は送信しません。

対応する通常フィールドは文字列1行・複数行・リッチエディター・数値・日付・時刻・日時・リンク・ドロップダウン・ラジオボタンです。自動計算・ルックアップコピー先は直接更新しません。サブテーブル・添付ファイル・複数選択等は今回の範囲外です。

終了判定・値変換は新規版と同じです。表示文字列ではなくExcelの生値を読みます。日付・日時のExcelシリアル値を日付文字列へ自動変換する機能は追加していません。

## 現在の仕様と補足

- 更新キー自体は照合専用とし、書き換えません。キーがE_XXXに含まれていても更新内容から除外します。
- キーのExcel列は読込範囲外でも指定できます。プレビューはキー列まで広げますが、更新する列の範囲は広げません。
- 各キーに「必須・重複禁止」の両方を要求します。1項目だけでも一意なため、2〜3項目はAND条件による追加照合です。「組合せだけ一意なら可」という仕様ではありません。
- キーは対応する通常の文字列1行・数値・日付・日時・リンクから選びます。自動計算・ルックアップ・ルックアップコピー先・テーブル内・レコード番号は選択対象外です。
- 空欄キーは、その行だけスキップします。複数キーの一部だけが空欄でも同様です。Excel内で同じキーの組合せが重複した場合は最初の行を採用し、2回目以降の行をスキップします（本人が確認・了承した扱い）。数値の1と1.0など、正規化すると同じキーになる値も重複として扱います。
- 空欄・重複・キー不一致は、最後の△エラーにExcel行番号・キー・理由をまとめます。他の有効な行の更新と、100件ずつの処理は継続します。
- 空欄以外の不正なキー値や、更新対象のセルエラーは全体の更新開始前に停止します。空欄・重複としてスキップする行の更新セルは評価しません。
- 終了判定列の空欄は、キーのチェックより先に読込終了条件として扱います。空欄キーの後続行も読み込む場合は、終了判定列をキーとは別の列にしてください。
- 不一致には「閲覧権限のある一致レコードを取得できなかった」場合も含みます。非公開レコードの存在を判定したとは扱いません。取得API自体の権限・通信エラーはスキップせず停止します。
- 空欄の更新セルは新規版の変換を引き継ぎ、空文字などを送信します。「空欄なら元の値を残す」オプションは未実装です。
- 一覧の絞り込み条件・現在ページに更新対象を限定せず、アプリ内の閲覧可能なレコードをExcelのキーで照合します。
- 更新にはアプリと更新対象レコード・フィールドの編集権限が必要です。アプリの設定を変更する管理権限とは別です。権限によるAPIエラーは新規版と同じくそのバッチで停止し、後続送信しません。
- 日付キーはYYYY-MM-DD、日時キーは秒・タイムゾーン付きの文字列。数値キーは精度を落とさない文字列の正規化で照合します。表示書式で付けた先頭ゼロは復元しません。

## 入力不備の行だけを飛ばす処理

更新APIが入力不備の行とフィールドを特定できた場合は、その行を△エラーとして除外し、同じ100件内の正常な行と後続の更新を続けます。権限・同時編集・通信エラーや、不備行を特定できないエラーでは停止します。

具体的には、CB_VA01のerrorsがすべて送信中の行番号と更新フィールドのvalueを指している場合だけ回復します。拒否されたPUTは全件取り消されるため、不備行を除いた未更新分だけを再送します。すでに成功したバッチを再送したり、最新のリビジョンを取得して上書きしたりはしません。再送のたびに元の画面状態も確認します。

例：201件のうち101件目だけが必須違反なら、100件成功→100件拒否→不備1件を除いた99件成功→最後の1件成功となり、更新200件・△1件です。すべての入力不備を事前に判別できる仕様ではありません。

## 更新の停止・同時編集

全行の読み取り・照合・重複チェックが完了してから、最大100件ずつ順番にPUTします。第1キーで候補を最大100件ずつ取得し、全キーが一致したID・リビジョンだけを更新に使います。新規登録APIは呼びません。PUTは`upsert:false`です。

照合後に他の人が更新していれば、リビジョン不一致でそのバッチは停止します。後続処理と自動再送はありません。それまでの成功分を巻き戻す機能はありません。通信途絶などでは送信対象が更新済みの可能性があるため、確認済み件数・対象Excel行・送信IDを表示します。

元の画面のアプリ・一覧表示イベント・ユーザーが変わったことを検知した場合も後続送信を停止します。確認画面の背後は通常操作できないため、この一覧変更の検証は模擬テストのみです。別タブでアプリの設定を更新したことを検知する機能ではありません。標準のアクセス権に従い、APIトークンを使わず操作ユーザーのセッションで処理します。

ボタン配置は既存版と同じ共通ルールV1で、自分の番号2だけを宣言します。新規1・削除3に変更は不要です。単独なら中央、3製品なら更新が中央になります。
